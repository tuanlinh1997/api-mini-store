# docs/backend/ — Folder Rules

**Owner**: @backend-developer
**Purpose**: How the backend works — services, business logic, and the API contract.

| File | What it is | Who edits |
|------|-----------|-----------|
| `BACKEND.md` | Module layout, auth flow, business logic domains, jobs, integrations | @backend-developer |
| `API.md` | Full endpoint reference — prose request/response contracts and business rules | @backend-developer |
| `openapi.json` | **Generated** OpenAPI 3 contract, the machine-readable source of truth (typed `data` schemas, named enums, per-endpoint error codes, `x-roles`). Never hand-edit; regenerate with `npm run openapi:export` | generated (@backend-developer commits it) |
| `api-types.ts` | **Generated** TypeScript types for the frontend (`openapi-typescript` from `openapi.json`). Never hand-edit; regenerated by `npm run openapi:export` | generated (@backend-developer commits it) |
| `api_integration_guide.md` | Vietnamese frontend integration guide: quick start, envelope, auth flow, permission matrix, conventions, business flows, error catalogue, endpoint reference | @backend-developer |
| `api_usage_guide.md` | Vietnamese API purpose and usage guide: screen-to-API map, every endpoint's purpose / when / where / who / side effects, end-to-end business scenarios, SRS traceability matrix, FAQ. A unit test fails if an operation of `openapi.json` is missing from it | @backend-developer |

## Rules

- `API.md` is updated in the same task that adds or changes an endpoint — an undocumented endpoint is an unfinished task. `openapi.json` is the source of truth for shapes; `API.md` stays the prose reference and must not contradict it.
- A task that changes an endpoint, DTO, response model, role or error code also runs `npm run openapi:export` and commits `openapi.json` and `api-types.ts`; `npm run openapi:check` fails when they are stale. Update `api_integration_guide.md` (flows, error catalogue and its two generated tables) in the same task.
- `api_integration_guide.md` and `api_usage_guide.md` are written in Vietnamese (the team's language); code, field names, enums and error codes stay in English.
- `api_usage_guide.md` documents purpose and usage (what / when / where / who), never schemas: link to `API.md`. A task that adds or removes an endpoint, or changes its role or side effects, also updates the matching `
- Database schema lives in `docs/database/DATABASE.md` — link, don't duplicate.
- @documentation-writer may improve readability, not endpoints, schemas, or status codes.
- Bigger features get their own `<feature_name>.md` in this folder (e.g. `inventory_management.md`) — start from `.claude/templates/docs/FEATURE_TEMPLATE.md`, use Mermaid diagrams where they clarify flows, and add the file to the table above.
- New files here require updating this table and the map in `docs/AGENTS.md`.
